## Go 基础

### 1. 模块、包和 main

- **模块**：由一个 `go.mod` 管理的一组包。Mini-Redis 的 [go.mod](../../go.mod) 只有三行：

  ```text
  module github.com/Li-Nepenthe/mini-redis

  go 1.26.0

  require golang.org/x/sys v0.50.0
  ```

  - 第一行是模块路径。
  - 第二行是语言版本：它决定能用哪些语法，也决定一些行为的默认值，比如第 8 小节讲的循环变量。写成 `1.26.0` 和写成 `1.26`，语言版本是一样的；区别只在于前者要求工具链至少是 1.26.0 正式版，后者连 1.26 的候选版也接受。
  - 第三行是依赖。项目只依赖一个外部模块 `golang.org/x/sys`，用来加文件锁（第 06 章），它由 Go 团队维护。依赖的校验和记录在 `go.sum` 里。

- **包**：一个目录就是一个包。目录里每个 `.go` 文件的第一行（注释除外）都写同一个 `package 名字`。
  - import 路径 = 模块路径 + 目录。例如 `github.com/Li-Nepenthe/mini-redis/database`。
  - 代码里用包名来引用，例如 `database.NewEngine(16)`。

- **入口**：`package main` 里的 `func main()` 是程序入口。Mini-Redis 有两个入口：
  - `cmd/server`：服务端；
  - `cmd/client`：命令行客户端。

  其他包都是库包，不能单独运行，只能被 import。

常用命令：

| 命令 | 作用 |
|---|---|
| `go run ./cmd/server` | 编译并运行，不留下可执行文件 |
| `go build -o mr.exe ./cmd/server` | 编译出可执行文件 |
| `go test ./...` | 运行所有包的测试，`./...` 表示当前目录及所有子目录 |
| `go vet ./...` | 静态检查常见错误，比如 Printf 的参数对不上、复制了锁 |
| `gofmt -l .` | 列出格式不规范的文件。Go 的代码格式由工具统一，不用争论缩进风格 |
| `go mod tidy` | 根据 import 补全或删除 go.mod 里的依赖 |

最小的 Go 程序：

```go
package main

import "fmt"

func main() {
	fmt.Println("hello, mini-redis")
}

// 输出：hello, mini-redis
```

### 2. 变量、常量和零值

声明变量有两种写法：

```go
var count int      // 完整写法：变量名在前，类型在后
name := "redis"    // 短声明：只能在函数内部用，类型由右边推断
a, b := 1, 2       // 一次声明多个
a, b = b, a        // 交换两个值，不需要临时变量
```

**零值**：声明了但没赋值的变量，自动是它类型的“零值”，不存在“未初始化”的状态。

| 类型 | 零值 |
|---|---|
| 数字 | `0` |
| string | `""` |
| bool | `false` |
| 指针、切片、map、channel、函数、接口 | `nil` |
| 结构体 | 每个字段都是各自的零值 |

零值的好处是：很多类型不初始化也能直接用。`sync.Mutex` 的零值就是一把没上锁的锁，`bytes.Buffer` 的零值就是一个空缓冲区。所以 Go 的结构体经常“声明出来就能用”，不需要构造函数。

但有一个例外要记住：**nil map 可以读，不能写**。

```go
package main

import "fmt"

type Server struct {
	Addr    string
	MaxConn int
	Debug   bool
}

func main() {
	var s Server
	fmt.Printf("%q %d %v\n", s.Addr, s.MaxConn, s.Debug)

	var m map[string]int
	fmt.Println(m["missing"], len(m)) // 读 nil map：返回零值，不报错

	defer func() { fmt.Println("recover:", recover()) }()
	m["k"] = 1 // 写 nil map：panic
}

// 输出：
// "" 0 false
// 0 0
// recover: assignment to entry in nil map
```

常量用 `const`。`iota` 在一组常量里从 0 开始，逐行加 1，常用来定义枚举：

```go
package main

import "fmt"

type State int

const (
	Running  State = iota // 0
	Draining              // 1：没写右边，就沿用上一行的表达式，iota 变成 1
	Stopped               // 2
)

func main() {
	fmt.Println(Running, Draining, Stopped)
}

// 输出：0 1 2
```

### 3. 基本类型

| 类型 | 说明 |
|---|---|
| `int`、`int64`、`uint64`… | `int` 在 64 位平台上是 64 位。需要固定宽度时（比如协议、文件格式）写 `int64` |
| `byte` | `uint8` 的别名，表示一个字节 |
| `rune` | `int32` 的别名，表示一个 Unicode 码点（一个“字符”） |
| `float64` | 浮点数 |
| `string` | 不可变的字节序列，第 01 章细讲 |
| `bool` | `true` / `false` |

Go 没有隐式类型转换。`int` 和 `int64` 相加，必须先写 `int64(x)` 转换。这样做的好处是不会因为自动转换悄悄截断或溢出。

### 4. 函数

```go
package main

import (
	"errors"
	"fmt"
)

// 多返回值：Go 的惯例是最后一个返回值是 error。
func divide(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("division by zero")
	}
	return a / b, nil
}

// 可变参数：在函数里 nums 就是一个 []int。
func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

// 函数也是值，可以作为返回值。返回的函数“记住”了外层的 count，这叫闭包。
func counter() func() int {
	count := 0
	return func() int {
		count++
		return count
	}
}

func main() {
	q, err := divide(7, 2)
	fmt.Println(q, err)
	_, err = divide(1, 0) // 用 _ 丢掉不需要的返回值
	fmt.Println(err)

	fmt.Println(sum(1, 2, 3))
	parts := []int{4, 5}
	fmt.Println(sum(parts...)) // 已有切片，用 ... 展开

	next := counter()
	next()
	fmt.Println(next())
}

// 输出：
// 3 <nil>
// division by zero
// 6
// 9
// 2
```

### 5. 控制流

- **if** 可以带一个初始化语句，变量只在 if 和 else 里有效：

  ```go
  if v, ok := m[key]; ok {
  	// 用 v
  }
  ```

- **for** 是唯一的循环关键字，没有 while：

  ```go
  for i := 0; i < 3; i++ {}  // 三段式
  for n < 100 {}             // 只有条件，相当于 while
  for {}                     // 死循环，用 break 或 return 退出
  for i, v := range s {}     // 遍历切片、数组、字符串、map、channel
  for i := range 3 {}        // Go 1.22 起可以 range 一个整数：i 依次是 0、1、2
  ```

- **switch** 每个分支执行完自动结束，不需要写 `break`。一个分支可以列多个值。不写条件的 `switch` 相当于一串 if-else：

  ```go
  switch cmd {
  case "GET", "EXISTS":
  	// 读命令
  case "SET":
  	// 写命令
  default:
  	// 未知命令
  }
  ```

  Mini-Redis 的 `Exec`（[database/engine.go](../../database/engine.go)）就是用一个 switch 按命令名分发的。

### 6. 指针

`&x` 取变量的地址，`*p` 通过指针读写它指向的变量。Go 的指针不能做加减运算，所以比 C 安全。

什么时候用指针：
- 函数要修改调用者的变量；
- 结构体很大，不想每次传参都复制一遍；
- 结构体里有锁，或者需要被多处共享同一份状态。这种类型必须用指针传递，复制一份锁就等于有了两把互不相干的锁。

```go
package main

import "fmt"

type Counter struct{ n int }

func (c *Counter) Inc()    { c.n++ } // 指针接收者：改的是调用者那一份
func (c Counter) Get() int { return c.n }

func main() {
	c := Counter{}
	c.Inc()
	c.Inc() // c 是变量，Go 会自动取地址，等价于 (&c).Inc()
	fmt.Println(c.Get())

	p := new(int) // new(T)：分配一个零值的 T，返回 *T
	*p = 42
	fmt.Println(*p)

	q := new(int64(7)) // Go 1.26 起：new 也可以接收一个表达式，用它作初始值
	fmt.Println(*q)
}

// 输出：
// 2
// 42
// 7
```

接收者该用指针还是值，第 03 章细讲。

### 7. 导出规则和 init

- **名字首字母大写就导出**，包外可以用；小写只能在包内用。这条规则对函数、类型、结构体字段、方法、常量都适用。Go 没有 public、private 这样的关键字。
- 只在包内使用的东西就写成小写。比如 database 包里的链表 `linkedList` 和节点 `node`，早期版本写成了大写的 `LinkedList`、`Node`，其实没有任何包外的代码用它们。改成小写以后，包的使用者只能看到真正需要的东西。整个项目导出的类型和函数从 43 个减到了 26 个（见文末的开发过程回放）。

**初始化顺序：**
1. 被 import 的包先初始化，依赖最深的最先。
2. 同一个包里，先初始化包级变量，按依赖关系排序。
3. 然后执行 `init()`。一个包可以有多个 `init`，按文件名顺序、文件内的先后顺序执行。
4. 最后执行 `main()`。

`init` 不能被手动调用，也没有参数和返回值。它适合做注册之类的事，但隐式执行的代码不好追踪，所以不要在里面做复杂的逻辑。Mini-Redis 没有用 `init`，所有初始化都在 `main` 里显式完成。

### 8. 循环变量（Go 1.22 的变化）

```go
package main

import "fmt"

func main() {
	var prints []func()
	for i := 0; i < 3; i++ {
		prints = append(prints, func() { fmt.Print(i, " ") })
	}
	for _, p := range prints {
		p()
	}
	fmt.Println()
}

// 输出（go.mod 里 go ≥ 1.22）：0 1 2
// 输出（go.mod 里 go < 1.22）：3 3 3
```

- Go 1.22 之前，整个循环只有一个变量 `i`，三个闭包引用的是同一个 `i`，循环结束时它是 3。
- Go 1.22 起，每次迭代都有一个新的 `i`。

用哪种行为，由 **go.mod 里的 go 版本**决定，而不是由安装的 Go 版本决定。Mini-Redis 是 `go 1.26.0`，所以是新行为。

## 代码走读：一条命令走过哪些包

先看包之间谁依赖谁。箭头表示“import 了”：

```text
cmd/server ──► server ──► resp
    │                       ▲
    ├────────► aof ─────────┘
    │
    └────────► database          （database 不 import 项目里的任何包）

cmd/client ──► resp
```

| 包 | 做什么 | 从哪里读起 |
|---|---|---|
| [cmd/server](../../cmd/server/main.go) | 进程入口：解析参数、恢复 AOF、启动网络服务、处理 Ctrl+C | `run` |
| [server](../../server/server.go) | 监听端口，每个连接一个 goroutine，读请求、执行、写回复，负责停机 | `Serve`、`handle` |
| [resp](../../resp/parser.go) | RESP 协议的字节格式：读一条请求、编码一条回复 | `ReadRequest`、`EncodeReply` |
| [database](../../database/engine.go) | 存储引擎：字符串、列表、过期时间、写日志的顺序 | `Exec` |
| [aof](../../aof/store.go) | 追加日志文件：启动时恢复、运行时追加并刷盘 | `Open`、`Append` |
| [cmd/client](../../cmd/client/main.go) | 交互式命令行客户端 | `runClient` |

每个包都有一个 `doc.go`，写了这个包解决什么问题、文件怎么分工、从哪里读起。读一个包之前，先读它的 doc.go。

客户端发来 `SET name redis`，依次经过：

1. [server/server.go](../../server/server.go) 的 `Serve` 循环 `Accept`，每接受一个连接，就在 `startConnection` 里登记它，并 `go s.handle(conn)`。
2. [server/connection.go](../../server/connection.go) 的 `handle` 调用 `resp.ReadRequest`，从连接上读出一条完整的请求，得到 `[][]byte{"SET", "name", "redis"}`。
3. `handle` 调用 `s.executor.Exec(args)`。这里的 `executor` 是一个只有 `Exec` 方法的接口，运行时装的是 `*database.Engine`。
4. [database/engine.go](../../database/engine.go) 的 `Exec` 把命令名转成大写，按命令名分发。SET 是写命令，进入 [database/write.go](../../database/write.go) 的 `executeWrite`：开了 AOF 时先写日志，日志落盘后才改内存，最后返回 `StatusReply("OK")`。
5. 回到 `handle`，`resp.EncodeReply` 把 `StatusReply("OK")` 编码成 `+OK\r\n`，`writeReply` 把这些字节写回连接。

[cmd/server/main.go](../../cmd/server/main.go) 负责把这些零件装在一起：

```go
func main() {
	addr := flag.String("addr", ":6379", "TCP listen address")
	aofPath := flag.String("aof", "data/appendonly.aof", "AOF file; empty disables persistence")
	flag.Parse()
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()
	if err := run(ctx, *addr, *aofPath); err != nil {
		log.Fatal(err)
	}
}
```

`main` 只做三件事：读命令行参数、把 Ctrl+C 变成一个会被取消的 ctx、调用 `run`。真正的组装在 `run` 里：

- 先 `net.Listen` 占住端口；
- `database.NewEngine(16)` 建一个 16 个分片的引擎；
- 开了 AOF 时，`aof.Open` 把日志里的历史命令重放进引擎，再用 `AttachLog` 把日志接到引擎上；
- 启动后台清理过期 key 的 goroutine；
- `server.NewServer` 建网络服务，`Serve` 开始接收连接，直到收到停机信号。

`run` 返回 error，而不是自己调用 `log.Fatal`。这样 [cmd/server/main_test.go](../../cmd/server/main_test.go) 可以直接调用 `run`，检查“启动时就收到取消”“端口被占用”这些情况，不用真的启动一个进程。

## Go 八股

### 八股 1：new 和 make 有什么区别？

#### 一分钟口述版

> `new(T)` 适用于任何类型：它分配一块 T 类型的零值内存，返回指向它的指针 `*T`。`make` 只能用于切片、map 和 channel 三种类型，返回的是这个类型本身，不是指针，而且会把它初始化成可以直接用的状态：切片会分配底层数组，map 会分配哈希表，channel 会分配缓冲区。之所以要区分，是因为这三种类型的零值是 nil，nil map 不能写，nil channel 读写会永远阻塞，必须用 make 初始化后才能正常用。实际写代码时 new 用得很少，一般用 `&T{...}` 这种写法，它在取地址的同时还能给字段赋初值。

#### 要点

| | `new` | `make` |
|---|---|---|
| 能用于 | 任何类型 | 只有 slice、map、chan |
| 返回 | `*T`，指针 | `T`，值本身 |
| 内存内容 | 零值 | 初始化好的、可直接使用的结构 |
| 参数 | 一个类型；Go 1.26 起也可以是一个表达式，比如 `new(int64(7))` | 类型，加上长度、容量等 |

- `make([]int, 3, 10)`：长度 3，容量 10。
- `make(map[string]int, 100)`：预估装 100 个元素，提前分配好空间，减少扩容。
- `make(chan int, 5)`：缓冲区大小为 5 的 channel。

#### 项目里的例子

- [database/engine.go](../../database/engine.go) 的 `NewEngine` 创建引擎时，用 `make` 建出每个分片的两个 map：`make(map[string]any)` 存数据，`make(map[string]expiration)` 存过期时间。如果用零值的 nil map，第一次 SET 就会 panic。分片的切片本身也是 `make([]*shard, shardCount)` 建的。
- 项目里几乎不用 `new`，而是写 `&Engine{...}` 这样的复合字面量取地址，同时给字段赋初值。

#### 常见追问

**追问 1：`new(map[string]int)` 得到的 map 能直接写吗？**

不能。它返回 `*map[string]int`，指向一个 nil map。写入会 panic：`assignment to entry in nil map`。

**追问 2：`new(T)` 和 `&T{}` 有什么区别？**

效果一样，都分配一个零值的 T 并返回指针。`&T{Field: v}` 还能在创建时给字段赋值，所以更常用。两者都不决定变量放在栈上还是堆上，这由编译器的逃逸分析决定（第 05 章）。

**追问 3：make 可以用于数组或结构体吗？**

不能。make 只认切片、map、channel 三种类型，用在别的类型上会编译报错。

### 八股 2：Go 只有值传递吗？

#### 一分钟口述版

> 是的，Go 的函数参数全部是值传递，传进去的都是一份拷贝。之所以有人觉得切片、map 是“引用传递”，是因为这些类型的值本身就含有指针：切片是一个三字段的结构（指向底层数组的指针、长度、容量），map 和 channel 本身就是指向运行时内部结构的指针。拷贝它们，拷贝的只是这个小小的“描述符”，背后的数据是共享的。所以在函数里修改切片的元素，外面能看到；但在函数里 append 导致长度变化，外面那个切片的长度不会变，因为长度存在描述符的副本里。

#### 要点

| 传入的类型 | 拷贝的是什么 | 在函数里修改，外面能看到吗 |
|---|---|---|
| int、string、结构体、**数组** | 整个值 | 看不到 |
| 指针 | 地址 | 通过指针改的能看到 |
| 切片 | 指针 + 长度 + 容量 | 改元素能看到；append 后的新长度看不到 |
| map、channel | 指向内部结构的指针 | 能看到 |
| 接口 | 类型信息 + 数据指针 | 取决于里面装的是什么 |

```go
package main

import "fmt"

func setFirst(s []int)        { s[0] = 100 }
func appendOne(s []int)       { s = append(s, 4) }
func putKey(m map[string]int) { m["k"] = 1 }
func setArray(a [3]int)       { a[0] = 100 }

func main() {
	s := []int{1, 2, 3}
	setFirst(s)
	fmt.Println(s) // 改元素：外面看得到

	appendOne(s)
	fmt.Println(s, len(s)) // append：外面的长度还是 3

	m := map[string]int{}
	putKey(m)
	fmt.Println(m)

	a := [3]int{1, 2, 3}
	setArray(a)
	fmt.Println(a) // 数组是值类型，整个被拷贝
}

// 输出：
// [100 2 3]
// [100 2 3] 3
// map[k:1]
// [1 2 3]
```

#### 项目里的例子

- **命令参数是切片**。`Exec(args [][]byte)` 拿到的是调用者切片的副本，但底层的字节是共享的。所以引擎要存一个值时，必须先拷贝一份。SET 和 LPUSH 的值都在 [database/write.go](../../database/write.go) 的 `planWrite` 里统一用 `bytes.Clone` 拷贝。返回给调用者的值也要拷贝，比如 GET 和 LRANGE 都返回 `bytes.Clone` 的结果。不然调用者后来改了自己的缓冲区，引擎里存的数据也会跟着变。第 01 章会用切片的底层结构解释这一点。
- **Engine 的方法都用指针接收者**。Engine 里有锁和 map，如果用值接收者，每次调用都会拷贝一份 Engine，包括里面的锁，锁就失效了。`go vet` 的 copylocks 检查专门抓这种错误。

#### 常见追问

**追问 1：那函数里要让外面看到 append 的结果，该怎么办？**

把新切片返回，让调用者接住：`s = appendOne(s)`。内置的 `append` 就是这样设计的。也可以传 `*[]int`，但很少这样写。

**追问 2：传大结构体用指针是不是一定更快？**

不一定。传指针可能让结构体逃逸到堆上，增加 GC 的负担；小结构体直接拷贝，往往更快。要不要用指针，主要看语义（是否需要修改、是否含锁），而不是看性能。

### 八股 3：Go 语言有什么特点？

#### 一分钟口述版

> 我觉得 Go 最大的特点是简单和工程化。语法很少，只有 25 个关键字，格式由 gofmt 统一，读别人的代码很快。编译快，编译出来是一个静态链接的可执行文件，部署时直接拷过去就能跑。并发是语言内置的：goroutine 很轻，开几万个都没问题，配合 channel 和 sync 包，可以用同步的写法写高并发的网络服务。它有垃圾回收，不用手动管理内存。标准库很全，网络、HTTP、加密、测试都有。工具链也是统一的：测试、基准、竞态检测、性能分析都内置在 go 命令里。缺点也有：错误处理要写很多 `if err != nil`；泛型 1.18 才加入，能力有限；GC 有停顿，不适合硬实时场景。

#### 要点

- **简单**：25 个关键字；没有类继承，用组合（结构体嵌入）和接口；没有异常，错误是返回值。
- **编译和部署**：编译快；默认静态链接，产出单个可执行文件；交叉编译只需要设置 `GOOS` 和 `GOARCH`。
- **并发**：goroutine 和 channel 是语言内置的，调度由运行时负责（第 02 章）。
- **内存管理**：并发的垃圾回收，STW 停顿很短（第 05 章）。
- **工具链**：`go test`、`-race`、`-bench`、`-fuzz`、`pprof` 都是官方提供的（第 08 章）。

#### 项目里的例子

- Mini-Redis 除了标准库，只依赖一个 `golang.org/x/sys`，用来调用各平台的文件锁。它是 Go 团队维护的扩展库。
- 一个连接一个 goroutine，代码按“读一条、执行、写回”的同步顺序写，不需要回调。这正是 goroutine 带来的写法上的简单（第 02 章）。
- [CI](../../.github/workflows/ci.yml) 里用同一套 go 命令完成格式检查、竞态检测、vet 和构建。只要把 `GOOS` 设成 windows 或 darwin 再跑一遍 vet，就能在 Linux 机器上检查另外两个平台的代码能不能编译。

#### 常见追问

**追问 1：Go 有继承吗？**

没有。Go 用**组合**代替继承：把一个类型嵌入到结构体里，它的字段和方法会“提升”到外层，可以直接调用。多态则靠接口实现，一个类型只要实现了接口要求的方法，就自动满足这个接口，不需要声明（第 03 章）。

**追问 2：为什么说 Go 适合写网络服务？**

网络服务的特点是连接多、大部分时间在等 IO。Go 让每个连接一个 goroutine，阻塞的网络读写由运行时的网络轮询器接管，不占用线程（第 02 章）。所以既有同步代码的可读性，又有接近事件驱动的效率。

### 八股 4：for 循环里的闭包为什么会出错？Go 1.22 改了什么？

#### 一分钟口述版

> Go 1.22 之前，for 循环里的循环变量在整个循环中只有一份，每次迭代只是修改它的值。如果在循环里创建闭包或者启动 goroutine，引用了这个变量，它们拿到的都是同一个变量，执行的时候往往已经是最后一次的值。以前的解决办法是在循环体里写一句 `i := i`，复制一份。Go 1.22 改了语义，每次迭代都创建一个新变量，这个问题就没有了。要注意，是否启用新语义，由 go.mod 里声明的 go 版本决定，而不是由编译器版本决定，这样老项目升级编译器时，行为不会悄悄改变。

#### 要点

- 例子见 Go 基础第 8 小节。
- 适用于三段式 for 循环和 `for range`。
- 旧代码里的 `i := i`、`v := v` 在 Go 1.22 之后已经不需要了，但留着也没有坏处。
- `go vet` 的 loopclosure 检查以前会对这种写法报警告；在新语义下，这一类问题已经不存在了。

#### 项目里的例子

> **项目里没有直接体现，但面试常问。** Mini-Redis 的 go.mod 是 `go 1.26.0`，用的是新语义。服务端为每个连接起 goroutine 时，写的是 `go s.handle(conn)`，`conn` 作为参数传进去，在 `go` 语句执行时就已经求值了，本来就不受这个问题影响。

#### 常见追问

**追问：这个改动会不会让性能变差？每次迭代都分配新变量？**

不会明显变差。只有当变量被闭包捕获、逃逸到堆上时，才会每次迭代分配一次；不被捕获的循环变量，编译器仍然放在栈上或寄存器里复用。

## 关键设计与为什么

**1. database 不 import 项目里的任何包。**
- 为什么：存储引擎是项目的核心，它不该关心请求从哪里来（TCP、测试、AOF 重放），也不该关心日志写到哪里。这样 [database/engine_test.go](../../database/engine_test.go) 可以直接调用 `Exec` 测命令语义，不用开端口。
- 日志怎么接进来：database 自己定义一个只有 `Append` 方法的 `CommandLog` 接口，aof 包的 `Store` 恰好有这个方法，`cmd/server` 把两者接上（第 03 章讲接口）。
- 放弃了什么：引擎里不能直接调用 aof 的函数，组装工作全部交给 `cmd/server`，多了一层间接。

**2. server 只认识一个 `Executor` 接口。**
- `server.NewServer(addr, executor)` 收的不是 `*database.Engine`，而是任何有 `Exec(args [][]byte) (any, error)` 方法的值。
- 这样停机测试可以塞进一个“故意卡住”的假执行器，制造“命令正在执行时收到停机”的场景（第 07 章），不用依赖真实引擎的执行速度。

**3. main 很薄，组装放在 run 里。**
- `main` 里只有参数、信号和错误退出；`run(ctx, addr, aofPath)` 返回 error。
- 测试可以直接调用 `run`，传入一个已经取消的 ctx 或一个被占用的端口，检查它能不能干净地退出、后台 goroutine 有没有收尾。

**4. 只导出外部真正用到的名字。**
- 导出的名字就是包的“使用说明书”：名字越少，使用者越容易看出该从哪里用起。database 包现在只导出 `Engine`、`NewEngine`、`StatusReply`、`CommandLog` 和几个错误变量，以及 `Exec`、`Replay`、`AttachLog`、`RunCleanup` 这几个方法。

`linkedList`、`shard`、`writePlan` 这些小写的名字都不会出现。再试试 `go doc ./database Engine`，看看 Engine 有哪些导出的方法。

**实验 2：从包外调用一个小写的方法。**

在仓库根目录建一个临时目录 `tmpexp`，写一个 `main.go`：

```go
package main

import (
	"fmt"

	"github.com/Li-Nepenthe/mini-redis/database"
)

func main() {
	e := database.NewEngine(16)
	fmt.Println(e.Exec([][]byte{[]byte("SET"), []byte("k"), []byte("v")}))
	fmt.Println(e.get([][]byte{[]byte("GET"), []byte("k")}))
}
```

运行 `go run ./tmpexp`，编译直接失败：

```text
tmpexp\main.go:12:16: e.get undefined (cannot refer to unexported method get)
```

把最后一行改成调用公开的入口，并多打印一次类型：

```go
	fmt.Println(e.Exec([][]byte{[]byte("GET"), []byte("k")}))
	reply, err := e.Exec([][]byte{[]byte("GET"), []byte("k")})
	fmt.Printf("%T %q %v\n", reply, reply, err)
```

输出：

```text
OK <nil>
[118] <nil>
[]uint8 "v" <nil>
```

GET 返回的是 `[]byte`，`Println` 把它当成数字列表打印，118 就是字母 v 的编码；用 `%q` 才能看到字符串的样子。`[]uint8` 就是 `[]byte`，`byte` 是 `uint8` 的别名。

**实验 3：传一个不是 2 的幂的分片数。**

## 常见误区

- **`:=` 遮蔽了外层变量。** 在 if 或 for 里写 `x, err := f()`，会新建一个只在这个块里有效的 err，外层的 err 没被赋值。函数末尾检查外层的 err，就会漏掉错误。
- **以为 nil map 什么都不能做。** 读 nil map 不会出错，会返回零值；只有写入才 panic。
- **以为 `for _, v := range s` 里改 v 能改到切片。** v 是元素的拷贝。要修改元素，写 `s[i] = ...`。
- **未使用的变量和 import 会编译报错。** 这是 Go 有意的设计，防止代码里留下死代码。临时不想用，可以写 `_ = x`。
- **把 go.mod 的 go 版本当成“最低编译器版本”的摆设。** 它会影响语言语义（循环变量）和一些 GODEBUG 默认值，改它要谨慎。

## 自测

先自己回答，再展开答案。

**1. 客户端发来 `SET name redis`，依次经过哪几个包、哪几个函数？**

<details><summary>答案</summary>

server 包的 `handle` 用 `resp.ReadRequest` 读出请求 → 调用 `Executor.Exec`，实际是 `database.Engine.Exec` → 写命令进入 `executeWrite`，开了 AOF 时先 `Append` 到日志再改内存 → 回到 `handle`，`resp.EncodeReply` 编码成 `+OK\r\n` → `writeReply` 写回连接。

</details>

**2. 项目里哪个包不 import 任何项目包？这样安排有什么好处？**

<details><summary>答案</summary>

database。引擎不关心请求来自网络、测试还是 AOF 重放，可以直接调用 `Exec` 做单元测试；日志通过它自己定义的 `CommandLog` 接口接进来，由 `cmd/server` 组装。

</details>

**3. `cmd/server` 为什么把逻辑放在 `run` 里，而不是全写在 `main` 里？**

<details><summary>答案</summary>

`main` 没有参数也没有返回值，出错只能退出进程，测试很难调用它。`run` 接收 ctx 和地址、返回 error，测试可以直接调用它，检查取消、端口冲突时能不能干净地退出。

</details>

**4. 在别的包里写 `e.get(args)` 会怎样？如果确实需要从包外读取，应该怎么做？**

<details><summary>答案</summary>

编译失败：`cannot refer to unexported method get`。小写开头的名字只能在包内使用。包外应该走公开的入口 `e.Exec([][]byte{[]byte("GET"), key})`。所有命令只从 `Exec` 一个入口进来，统一命令名的大小写、拒绝客户端发来的私有 AOF 标记，都只需要在这一处做。

</details>

**5. `fmt.Println` 打印 GET 的返回值，为什么看到的是 `[118]`？**

<details><summary>答案</summary>

GET 返回 `[]byte`。`Println` 按 `%v` 打印字节切片，结果是一列数字；118 是 v 的编码。用 `%q` 或先转成 `string` 才能看到文字。

</details>

**6. 写一个 `var m map[string]int`，然后 `m["a"] = 1`，会怎样？`NewEngine` 是怎么避免这个问题的？**

<details><summary>答案</summary>

panic：`assignment to entry in nil map`。map 的零值是 nil，可以读，不能写。`NewEngine` 用 `make` 为每个分片建好 `data` 和 `expires` 两个 map。

</details>
